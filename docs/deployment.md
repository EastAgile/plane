# Deployment

## Docker Compose (Self-Hosting)

### Production Setup

```bash
# 1. Initial setup
./setup.sh

# 2. Configure environment variables in .env files

# 3. Start production stack
docker compose up -d

# 4. Access via Nginx
# Default: http://localhost:9999
```

### Upgrading

```bash
./setup.sh upgrade    # Pull latest images and restart
```

### Docker Images

| Image | Source | Description |
|-------|--------|-------------|
| `plane-frontend` | `/web` | Main web application |
| `plane-admin` | `/admin` | Admin dashboard |
| `plane-space` | `/space` | Public issue viewer |
| `plane-live` | `/live` | Real-time server |
| `plane-backend` | `/apiserver` | Django API + Celery workers |
| `plane-proxy` | `/nginx` | Nginx reverse proxy |

### Volumes

Production Docker Compose uses named volumes for data persistence:
- PostgreSQL data
- Redis data
- MinIO object storage
- Upload artifacts

## CI/CD

GitHub Actions workflows are in `.github/workflows/`:

| Workflow | Trigger | Purpose |
|----------|---------|---------|
| `build-branch.yml` | Manual dispatch | Build and push Docker images |
| `build-test-pull-request.yml` | Pull requests | Run tests on PRs |
| `feature-deployment.yml` | Feature branches | Deploy feature environments |
| `build-aio-branch.yml` | Manual dispatch | Build all-in-one image |
| `codeql.yml` | Push/PR | Security scanning |
| `check-version.yml` | Push | Version validation |

### Build Pipeline

The main build workflow (`build-branch.yml`):
1. Builds Docker images for all services
2. Supports multi-platform: `linux/amd64`, `linux/arm64`
3. Pushes to Docker Hub under `makeplane/*`
4. Supports release versioning and pre-releases

## All-in-One (AIO) Container

The `/aio` directory provides a single-container deployment option that bundles all services. Useful for evaluation and small-scale deployments.

## Infrastructure Requirements

### Minimum (Small Team)
- 2 vCPU, 4 GB RAM
- 20 GB disk
- PostgreSQL 15+
- Redis 7+

### Recommended (Production)
- 4+ vCPU, 8+ GB RAM
- 50+ GB SSD
- Managed PostgreSQL
- Managed Redis
- S3-compatible object storage
- Load balancer with SSL termination

## Environment Configuration

### Key Production Variables

| Variable | Description |
|----------|-------------|
| `SECRET_KEY` | Django secret key (auto-generated by setup.sh) |
| `DATABASE_URL` | PostgreSQL connection string |
| `REDIS_URL` | Redis connection string |
| `AWS_S3_BUCKET_NAME` | S3 bucket for file storage |
| `WEB_URL` | Public URL of the web application |
| `CORS_ALLOWED_ORIGINS` | Allowed CORS origins |
| `SENTRY_DSN` | Error tracking (optional) |
| `NGINX_PORT` | Reverse proxy port (default: 9999) |
